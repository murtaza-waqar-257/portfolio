Driverbot is a WhatsApp assistant for a delivery company in Italy with 40 vans. The bot checks each van for new damage. It reads the delivery notes. It follows the vans with GPS. It sends a message to the boss only when there is a problem.

Before Driverbot, the work day ran on phone calls.

Small delivery companies use WhatsApp and the phone for all their work. Each morning, the office asks the drivers the same questions. When a van has new damage, nobody knows who caused it. The office finds an unsigned delivery note only when it does the paperwork. Sometimes this is one week later.

The drivers did not want a new app. For this reason, the assistant works in WhatsApp, where the drivers already are.

    How it is built.

    One program follows the steps of the driver's day. The program uses AI only to read photos, delivery notes and Maps screenshots. All other parts are simple code that always does the same thing.

    1. Select a flow. The diagram shows how the message moves through the system.

    Fixed steps, not a free agent

    The day of a driver has the same steps each time. For this reason, the bot follows fixed steps. The bot uses AI only where a person must look at something: a photo, a signature or a screenshot.

    In the app that the drivers use

    The drivers do not install a new app. They send photos in WhatsApp, as before. The boss reads the updates for each driver.

    Safe by default

    The GPS login can only read data. It cannot change data. The photos are in a private store, and only the key of the bot can open it. The keys are not in the code.

    What I learned.

    • A van arrives only when it stops.

      ProblemThe first version said "arrived" when a van came within 3 km of the town. This also occurred when the van went past at 55 km/h.

      CorrectionNow the bot waits until the van parks.

    • Message costs change the design.

      ProblemWhatsApp charges for each message that the bot sends. With 40 vans, the cost increases quickly.

      CorrectionThe bot sends only the problems to the boss. His updates can go to a channel that is free.

    • Time zones can cause errors.

      ProblemA Maps screenshot from a UK phone showed a time that was one hour wrong. This caused a false "late" alert.

      CorrectionNow the bot uses the trip duration, not the clock in the screenshot.

    • Make the plan before you build.

      ProblemThe requirements came one at a time, and the code grew with them.

      CorrectionNext time, I will make the flowchart, the costs and the special cases first.
